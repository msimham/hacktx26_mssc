# Setup: what you need to do

**You can run everything without doing any of this.** With no `.env`, every integration is a labeled mock or rules fallback and the whole game, the Builder and the Results all work. Each step below switches one real service on. No real API call has been made by the implementer, so after each step, check the **Status** button (top right of every page): a service only shows **Live** after a real request has succeeded.

Run all commands from `magicalsafety/`.

## 0. Install and run

```bash
npm install
npm run dev          # server http://localhost:3001, client http://localhost:5173
npm test             # all tests (none contacts a real service)
npm run check:secrets
```

Node 22 or newer. Copy `.env.example` to `.env` for any of the steps below (`.env` is git-ignored; never commit it).

## How to confirm each one works

1. **Meta key** → restart `npm run dev` → **Status**: Muse Spark/Image/Voice show *Configured, not yet verified*. Finish a game: the interpretation says **Generated by muse-spark-1.3** and Muse Spark flips to **Live**. If it fails you will see **Degraded** and the labeled fallback, and the game keeps going. Open the Inspector to see exactly what was sent and returned.
2. **Art** → `npm run gen:assets`, reload: scenes show "Muse art (cached)" and Muse Image shows *Cached art*.
3. **Voice** → tick **Voice** in Session Setup, press 🎙 Talk in the game, speak: label reads **Muse Voice**; Status shows **Live** after a success.
4. **SerpApi** → Builder → Research: results have real links and no `MOCK` badge.
5. **Facebook** → open the lobby as a tester: **Share on Facebook** and **Use my Facebook name** appear.
6. `npm run check:secrets` → confirms no key or token is stored on disk or committed.

After a real request works, tell the implementer the date and model id so `docs/INTEGRATIONS.md` can record it.

## Where things are stored

- `server/data/` (git-ignored): sessions (a small metadata file and a hash-chained input log each), analyses, agent run logs, tool audit, recap images, shout-outs, and organizations. Only a **hash** of each player's token is kept. Audio is never stored. Finished sessions are deleted after the organization's retention period (default 30 days) when the server starts.
- `server/assets-cache/` (git-ignored): generated art.
- Nothing is sent to any third party unless you add a key.

## Hosting it for others

`npm run build && npm start` serves the built client and API from one process on `PORT` (default 3001). It is a single long-lived Node process (WebSockets need one), so use a host that allows that rather than a serverless platform. Set `ORGANIZER_PASSCODE`, and `PUBLIC_ORIGIN` if browsers will reach it through a different address. The server sends a Content-Security-Policy, which has been tested for its headers but **not yet verified in a real browser**.
