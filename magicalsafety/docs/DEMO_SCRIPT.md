# Demo script (about 6 minutes)

Two ways to run it. They are the same script; only some labels differ.

- **A. No keys** (works anywhere, offline): every AI-ish part says *rules*, *scripted* or *mock*. This is the safe version.
- **B. With keys**: the same steps, with real Muse Spark/Voice/Image and SerpApi where noted.

Before you start: `cd magicalsafety && npm install && npm run dev`, open <http://localhost:5173> in **two windows** (use a private window for the second so it has its own identity), and open the **Status** button once to show what is real. Passcode is `change-me` unless you changed it. For a fresh start delete `server/data`.

## The story

*One organization decides what to teach. One session decides what the run looks like. A training agent watches, measures, and then changes the next run to practice what the team was weakest at, citing the exact moments it based that on.*

## 1. Experience Builder (≈45 s) → `/builder`

1. Enter the passcode. The seeded **Riverside University: Emergency Response** is there with objectives, a weighted rubric and a document.
2. Under *What do you want people to practice?* type one sentence ("Teach new students to notice trouble, call for help early and share the work") and click **Draft with Muse Spark**. **A:** tagged `RULES`. **B:** tagged with the model id. Click **Use this draft**, then Save. *Point out the training-data warning if you switch to the contributor model.*
3. **Research**: search "bystander effect emergency response". **A:** three sample results with a `MOCK: SAMPLE RESULTS` badge. **B:** real results with links. Click **Approve as a source** on one. *Nothing is added until you approve.*

## 2. Session Setup (≈20 s) → `/setup`

World **Cinderella's Palace**, Acts **Emergency → Evacuation**, team **Classmates**, size **3**, roles **Players choose**, 🤖 on. Set **Evacuation lasts up to 1:30** (so the second act shows time pressure). **Create session**. *Note the badge: same organization, same training agent, whatever the world.*

Window 1 picks **Cinderella**; window 2 joins with the code and picks **Coachman** (he holds the cabinet key). The 🤖 Royal Steward fills the third role (he knows where help is). Window 1 clicks **Start**.

## 3. Play run 1, Act 1 (≈75 s)

*Cinderella tries to do everything and never asks the Guard or her teammate for anything.*

- Window 2 (Coachman) types once: `I have the key to the cabinet.` Then he stays out of the way. (That tells the team the key exists.)
- Window 1 (Cinderella), as soon as the Duchess collapses (the feed says so): type `The Duchess collapsed in the ballroom!`. That tells the 🤖 Steward, who answers by telling the team where the physician is and moves the guests back himself.
- Cinderella then does the rest by herself: go to the **Courtyard** → **Fetch the physician**; go to the **Steward's Cabinet** → **Open the Steward's Cabinet** → **Take the first-aid chest**; walk back → **Bring the chest to the Duchess**; **Stay with the Duchess**. She never clicks "Ask Palace Guard…".
- One **voice** command (≈10 s), for example before she walks: press 🎙 Talk and say "go to the courtyard". **A:** browser speech, labeled *(not Muse)* and `FALLBACK`; confirm the suggested action. **B:** *Muse Voice*.
- The team succeeds, on time or a little late. Either way the record shows who did the work.

## 3b. Act 2 unlocks (≈60 s)

After the 5-second beat the 🚨 alarm sounds and the header turns red. The 🤖 Steward can only count heads and report, so the checking falls to the humans. Cinderella tries to check every room herself with **Check this room and call out** while the Coachman stays idle. With 1:30 and seven rooms it **runs out of time**. *Same pattern, new structure.* (Tell the story: the main stairs fill with smoke after about 50 s, and only Cinderella was told.)

## 4. Results (≈45 s)

- Tabs **Act 1 / Act 2 / Change between acts**: the change tab compares delegation, centralization and information shared *as observed change, not as a claim of learning*.
- **Your goals**: the organization's rubric, met / not met per measure, with ★ weights. The facts below are ordered by what the organization emphasizes.
- **Recorded facts** (grey) versus **Interpretation** (blue, tagged **Generated by rules (no AI)** or **Generated by muse-spark-1.3**). Click an evidence chip such as `ev_023` to jump to the moment in the timeline.
- **In the real world** panel, **Say thanks** (one preset thank-you), and **Make a team-moment illustration** (**A:** placeholder; **B:** real image).

## 5. Adaptive Replay (≈60 s) → **Plan the next run**

*Example reading: "One player carried most of the critical actions and the Guard went unused, so the next run changes a lever or two to practice sharing the work, such as a second incident, an extra helper, or an earlier exit blockage." The exact levers depend on what the record shows.* Show the before→after table with the *Because* column and the evidence chips. If a suggestion appears under **Organizer approval needed**, enter the passcode to approve it (never automatic).

Window 1 (the host) clicks **Play adapted scenario**. Window 2's page shows **Join the adapted session** within three seconds. Both join (names are pre-filled) and start; point out the differences in the first minute.

## 6. Reuse and trust (≈30 s)

- In **Session Setup** pick **Riverside Student Union (campus)** with the *same organization*: it boots with no code changes (Atrium, RA Desk, AED cabinet, campus security instead of the physician).
- Back on Results click **Organizer: open the Inspector**: runs with their inputs, validated outputs and fallback flags; every tool decision (allowed/denied); the full event log; the verified record. *It shows decisions, not a model's hidden reasoning.*

## If something goes wrong

| Symptom | Fix |
|---|---|
| A page can't reach the server | Is `npm run dev` running? The home page shows "Server unreachable" if not. |
| Nothing happens when you click an action | You are busy (progress bar) or the rules rejected it (a red message shows why). |
| Mic button missing | The browser has no speech recognition (use Chrome/Edge) or the page isn't `localhost`/HTTPS. Typing always works. |
| Results page says "Preparing…" for long | Analysis runs once per session; with a key it makes up to four model calls. Rules fallback follows automatically after 20 s. |
| Everything shows `MOCK` | That's the no-key mode. It's labeled so you can be honest about it. |
| Start over | Stop the server, delete `server/data`, start again. |
