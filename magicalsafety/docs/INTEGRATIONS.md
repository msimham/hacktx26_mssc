# Integrations: what is live, mocked, or unverified

Status words are used strictly:
- **Live**: a real request succeeded. Only recorded here after it happened, with date and model id.
- **Implemented, unverified**: code exists and is tested against a local stub; never run against the real service.
- **Mock / fallback**: the labeled fallback is what runs.
- **Not built**: planned, not yet implemented.

## Muse Spark: what was and wasn't checked

Checked against the docs (https://dev.meta.ai/docs/structured-output, /error-handling, 2026-10-24):
- `response_format: { type: "json_schema", json_schema: { name, schema, strict: true } }`.
- Strict mode needs `additionalProperties: false` on every object and every key in `required`; no `oneOf`/`allOf`.
- Error envelope `{ error: { message, type, param, code } }`; 429/500/503 retryable, 504 and other 4xx not.

Checked only against a local stub server (see `server/src/agent.test.ts`): our request path, bearer header, body shape, usage parsing, error mapping and timeout handling.

Open `TODO(VERIFY)` items: `usage.prompt_tokens/completion_tokens` field names in a real response; whether min/max keywords are accepted under strict mode (we strip them either way).

## Data sent to Meta when a key is set

Event ids, timings, role names, short chat excerpts (max 200 chars) and computed metrics. No real names, tokens or secrets. Contributor mode (cheaper, but content may be used to train Meta models) is never used unless an organizer opts in (setting arrives in Phase 4).
